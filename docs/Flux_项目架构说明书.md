# Flux 项目架构说明书

版本：1.0 · 更新日期：2026-09-21 · 读者：项目开发者/维护者

本文是重写版的产品与架构基线，由原开发规划及开发者已勾选的审阅清单合并而成。这里只定义新 Flux，不沿用旧项目的实现状态。已批准的目标不等于已经实现；当前进度以 [AI 开发手册](./Flux_AI开发手册.md) 为准，对外介绍见 [README](../README.md)。原审阅稿保留为历史依据，不再作为并行维护的需求源。

## 1. 项目定位与决策

Flux 是本地优先、由用户自备 AI 和搜索服务的新闻与 RSS 阅读器。核心是订阅阅读、带引用的每日新闻总结、联网证据核对与跨设备阅读状态，而不是浏览器、云端账号平台或通用自主代理。

### 1.1 合并后的产品基线

D-01–D-13 主要承接开发者审阅决定；MIT、状态管理方案、搜索预设、20:00 默认时间及未指定的预算数值由本轮在授权范围内补全，属于可调整的工程基线，不冒充开发者逐条指定的数值。D-15 是对相互冲突意见的显式解释。

### 1.2 审阅冲突的明确处理

审阅第一项写“翻页首发”，后面的专项回答又写“跨块选词和桌面翻页可以后做”。本次采用后一个、更具体的答复：首发有单块选词、滚动专注阅读；跨块选择和桌面分页属于后续阶段。此解释记录为 D-15，若开发者改回首发，必须同步更改阶段出口和任务依赖，不能只改 README。

“正常 LaTeX”落实为常用 LaTeX 数学表达式，不是完整 TeX 文档编译器。首发支持范围见第 4 节；不能执行宏文件、shell escape 或通过在线网页公式服务绕过无 WebView 约束。

## 2. 语言、框架与总体架构

### 2.1 技术栈基线

| 层面 | 选择 | 边界 |
| --- | --- | --- |
| UI 与主要业务 | Dart + Flutter 的桌面/移动目标 | 不生成 Web 版本，不接入 WebView。Flutter 自绘组件不是系统原生控件，桌面习惯仍须适配。 |
| 状态管理/依赖注入 | Riverpod | 一套主状态管理；简单组件内部状态不强制跨层共享。 |
| 数据库 | SQLite + Drift | 迁移、事务和查询集中管理；正文/设置唯一持久化来源，不把 JSON 和数据库同时作为权威。 |
| HTTP/流式请求 | Dart HTTP 客户端适配层，优先评估 Dio | 支持取消、流式事件、限流和脱敏；业务层不依赖某家 SDK。 |
| 文档渲染 | 受控文档树 + Flutter 组件 | HTML/Markdown 先解析；数学和高亮库经无 WebView、许可证与混排验证后锁定。 |
| 平台桥接 | macOS 必要时 Swift/AppKit；Android 必要时 Kotlin | 仅用于安全存储、文件/分享、后台任务、菜单等平台边界，不复制全套业务。 |
| 配置与国际化 | 类型化设置 + zh-CN/en 资源 | 本次三份文档仅中文，应用仍预留并交付中英文 UI。 |
| 安全存储 | macOS Keychain；Android Keystore 保护加密密钥 | Android 凭据用该密钥加密存入私有存储，不当作明文偏好。 |
| 美术 | 自制 SVG + 有许可证的必要字体 | 不依赖在线字体、网页图标库或重型绘图运行时。 |

具体 Flutter/Dart、Xcode、JDK、SDK、Gradle 和插件版本在 T005 锁定，保存工具链输出与 lockfile。不能凭日期猜兼容版本，也不能为编译方便暗自降低 macOS 27/Android 17 的最低系统目标。Android API 数值和 macOS deployment target 由官方平台资料与实际工具链验证后记录；目标系统版本不是“目前已支持”的声明。

### 2.2 模块与依赖方向

展示层调用用例层，用例层依赖领域规则和接口；基础设施实现这些接口。组合入口负责注入具体实现。页面不能直接操作数据库或调用付费 API。

模块结构：

    Flux 客户端（模块化单体，无业务后端）
    ├── app：启动、导航、主题、国际化、依赖组装
    ├── presentation：今日、订阅、阅读、我的、设置页面
    ├── application：刷新、翻译、总结、同步、备份、清理等用例
    ├── domain：文章身份、三态阅读、引用、预算、冲突规则
    └── infrastructure
        ├── local：SQLite/Drift、资源缓存、诊断
        ├── network：RSS/静态网页、AI/Search 适配器、WebDAV
        └── platform：安全存储、文件、分享、外部浏览器、后台调度

依赖接口只设置在需要替换/测试的边界：FeedFetcher、ArticleRepository、AIProvider、SearchProvider、StaticPageFetcher、CredentialStore、SyncTransport、PlatformScheduler。不要建立微服务、远端代理、任意代码插件市场或泛型工厂体系。

计划目录：

    ├── lib/core/                 # 错误、时钟、预算、设置、设计 token
    ├── lib/features/            # feeds/articles/news/ai/settings/sync/statistics

这是未来目录规范，不表示当前已生成工程。本轮三份文档在同一审阅目录，链接采用相邻文件；T006 放入仓库时统一调整链接，不维护多份不同步副本。

### 2.3 网络与数据流

    RSS/Atom ─HTTP→ 解析/清洗/去重 ─→ SQLite ─→ 本地阅读/搜索
    用户主动获取原站 ─HTTP→ 静态 HTML 提取 ─→ 正文修订
    新闻任务 ─→ 输入快照 + 搜索/静态获取 + 可选图像理解
             └→ 提供商适配器 ─→ 引用校验/证据状态 ─→ 本地总结版本
    本地共通设置/阅读状态 ←→ WebDAV 快照与条件发布
    原文链接/动态网页 ─→ 操作系统默认外部浏览器

本地优先不等于数据永不离开设备。AI 会接收所需正文/选区/图片，搜索服务接收查询，媒体站点看到网络请求，WebDAV 保存同步内容。首次配置逐项告知接收者，日志不得记录秘密和不必要正文。

## 4. 功能契约

### 4.1 订阅、文章和状态（F-RSS、F-STATE）

- RSS 2.0、Atom 为首发格式，订阅导入导出采用 OPML。导入可选“保留分组/全部未分类”，默认未分类以延续原交互；预览重复、无效和成功项，逐项取消/重试，不因一个失败源撤销全部结果。
- OPML 交换标准订阅地址、名称及分组，不保证保留 Flux 内部 ID、加精/刷新偏好或阅读状态。重复导入按规范地址匹配已有订阅，不重置其状态；跨设备稳定 ID 由同步协议维护，完整恢复使用备份。不得为实现 OPML 往返而伪造通用格式不包含的字段。
- 分组支持创建、重命名、删除、拖动/菜单排序、置顶及展开。未分类为保留组。删除分组选择移动到未分类或删除其中订阅；后一种复用删除订阅的收藏保留规则。
- Feed 使用跨设备稳定 ID，GUID 仅在该 Feed 范围内识别文章。无 GUID 时按规范化链接，再按来源、标题、时间指纹兜底；不随意剥离 URL 查询参数。正文哈希判断修订，不作为每次新增身份。
- 刷新有条件请求、取消、限并发，区分 304、没有新文章、部分解析失败和网络失败；保留旧内容。XML 禁外部实体/DTD，设响应、解压、图片尺寸和解析深度上限。
- 单一阅读字段 readingState = unread / read / later；不存在“已读且稍后再读”的双状态。首次成功呈现正文默认 unread→read，预加载/悬停/AI 阅读不触发。later 打开后仍为 later，用户点“标为已读”才变 read；手动可在三值间切换。仅未读筛选只匹配 unread，later 有独立入口。收藏 favorite 独立，不改变阅读状态。
- 加精显示加精标识与强调，但不影响排序之外的选材权重；总结选材只由来源设置控制。加精与分组置顶不同。
- 删除订阅时默认勾选“保留收藏文章”，展示收藏与其他文章数量。所有非收藏文章（包括 later）清理；保留收藏从源中脱离，带来源快照进入资料库。取消保留则清理全部。此操作的范围在同步前也必须可见，不能用常规缓存清理代替。
- 发布时间未知则使用抓取时间排序并注明；相同时间用稳定身份作次序。上下篇基于进入详情时的筛选/排序快照。列表分页/虚拟化，重返时恢复位置。
- 摘要优先源内摘要；缺失时按用户开关生成 AI 摘要或截取正文。未配置 AI、失败或达到预算时回退正文片段，不阻塞卡片；滚动本身不能反复计费。

### 4.2 正文与搜索（F-READ、F-RENDER、F-SEARCH）

- 正文完整性记录 sourceBody / summaryOnly / extracted / unknown，不把源内 content 字段绝对当全文。主动提取只用 HTTP + 静态解析，不执行脚本、不绕过登录/付费墙/验证码；失败保留原内容并给外部浏览器入口。
- 渲染受控文档树：标题、段落、强调、引用、列表、链接、图片、表格、行内代码、围栏代码块；拒绝脚本、事件属性、iframe、表单和危险 URL。代码静态高亮，可折叠及复制；未知语言按纯文本显示。
- 数学首发验收覆盖 `$...$`、`$$...$$`、上下标、分数、根式、求和/积分、希腊字母、括号伸缩、矩阵、分段和对齐等常用 LaTeX 数学语法。具体命令支持表由 T004 的 fixture 固化；不支持命令显示原式与提示，不能空白或冒充成功。不承诺任意宏包或完整文档编译。
- 单块选区可复制、查询、全选正文纯文本；跨控件拖动选择后做，不影响先提供“复制全文”。选词仅发送选区和最少上下文。译文与原文按段落关联，原文始终保留；超长翻译分段、可取消，只重试失败段。
- 图片按需缓存，预留尺寸，失败不阻塞文章；查看器支持返回，保存走系统接口。外链先显示网址及复制/打开按钮；系统分享不可用时回退复制，不保证每个平台均有 QQ/微信目标。
- 本地全库搜索标题/作者/来源/摘要/已存正文，文章内查找独立。SQLite FTS5 需实测中文 tokenizer；确定子串/词匹配语义，不能假设默认 tokenizer 已解决中文。搜索不访问未收录网页。
- 专注模式保留可发现退出入口、Esc/系统返回，双击只是附加方式。后续桌面分页需处理长块、图片跨页、字号重排和锚点恢复，不可用隐藏滚动条伪装。

### 4.3 AI 供应商、搜索与视觉（F-AI）

编码模型 DeepSeek V4.1 Flash 不等于软件必须使用它处理用户内容。业务以能力路由，不凭模型名猜能力。

| 接入层 | 首发适配目标 | 实施边界 |
| --- | --- | --- |
| 文本/视觉协议 | OpenAI Responses、OpenAI Chat Completions 兼容、Anthropic Messages | 三种独立适配器，不能只改 URL；流式、工具参数和图片编码分别验证。 |
| 提供商预设 | OpenAI、Anthropic、DeepSeek、千问/Qwen、MiMo、OpenCode | 预设映射协议、端点和认证方式。OpenCode 按其公开的模型/API 服务核对，不把编码 CLI、账号登录、套餐或任意代理自动当作公共 API。未验证的条目标明待验证/不可用。 |
| 自定义模型 | 协议 + Base URL + 模型 ID + 凭据 + 能力声明 | 列表接口不存在时允许手填；真实生成测试可能收费。 |
| 搜索协议 | SearchProvider 统一结果结构；首批选 Tavily、Brave Search 及自建 SearXNG 适配任务 | 这些是本次委托下的初始实现选择，端点、认证、条款和分页需在 T031 依据官方文档核对；不承诺无 Key 免费公网服务。 |
| 网页获取 | StaticPageFetcher | 返回已清洗文字、标题、图像引用、来源 URL、抓取时间和结果状态。 |

工具层至少支持 search(query)、fetchPage(url)、inspectImage(imageRef)。客户端校验参数、网络目的地和预算后执行，模型没有任意 HTTP、文件或 shell 权限。不具备原生 tool calling 的文本模型仍可使用客户端预先执行的必访/搜索结果，再生成总结；不能因此取消首发联网能力。

视觉用于理解新闻图片和静态网页中的图片。优先指定视觉模型，其次有视觉能力的主模型；均无视觉能力时跳过图像分析并明确标签，文本搜索/抓取/总结仍正常工作。不能通过本地浏览器截图执行动态网页，也不能说“访问了”只在 prompt 中出现却没实际获取的网址。

### 4.4 每日总结与核验（F-NEWS）

    定时/手动触发 → 预算与配置检查 → 固化设备时区/输入快照
    → RSS 选材 + 必访网站 + 搜索 → 事件聚合/去重
    → 生成带候选引用的条目 → 独立来源核对/冲突记录
    → 结构与引用校验 → 保存新版本/保留上个成功版本

- 必访网站任务从来源设置组成总 prompt，并由任务执行器逐站落实。即使用户手改总 prompt，原必访任务也不静默消失；提供明确的可视化/高级覆盖模式和差异预览。
- 重要事实尝试至少两个独立来源；转载同一稿件不能算两个证据。没有足够证据时标“来源单一/材料不足”，不同来源矛盾标“来源冲突”，只读 RSS 标“未联网核验”；不可声称保证真实性或输出模型自报的概率。
- 搜索查询排除词与内容主题排除词分开。服务商内部行为不能保证完全受客户端控制，但实际发送的查询和纳入结果必须符合本地规则。
- 引用只可使用真实获取的 sourceId，保存标题、URL、时间、最小摘录和材料哈希；摘要、全文、搜索片段分别标明。不存在的引用导致校验失败/条目退回，不把模型编造网址当证据。
- 日界线和展示采用设备时区，任务中途不改变；历史资料覆盖不完整需说明。历史结果保存日期+时区，旅行后可查旧记录而不重写日期。
- 定时默认每天设备当地时间 20:00（本次确定的可改默认值），启用开关默认开；后台尽力执行，不要求系统精确定时。错过计划后在下一次可运行时仅补当日一次，不补跑所有历史日期；当天成功版本存在则不重复自动收费，手动可再生成。
- 没有 Key/搜索配置或首次费用告知未确认时任务为 waitingConfiguration，保留“默认开启”偏好但不请求。多个设备各保存自己的总结且各自调度，可能产生多份费用；设置引导明确提示可关闭非主设备的自动执行。执行开关是本机项，计划时间/内容预算是共通项。
- 总时限默认 10 分钟，含排队、抓取、模型尝试、核验和保存前校验；预算不足时停止，部分结果清楚标注，完整成功版本不被覆盖。仅靠时间不能控制费用，因此还限制条目、请求、工具轮数和累计 Token。

### 4.5 无响应、错误与预算

同一模型在同一任务内连续五次“无可用响应”才按序故障转移；首个有效成功结果重置连续计数。不允许多个后台请求超时后仍并发挂着：先取消上一尝试再重试。默认首响应等待 45 秒，流式停滞 30 秒，单次硬时限 120 秒；重试等待 2/4/8/16 秒并计入总 10 分钟。到总时限或预算即结束，即使还没凑足五次；这是总资源边界，不承诺每次一定有时间尝试下一模型。

- 可重试：超时、连接中断、临时 5xx；429 遵守 Retry-After，超过剩余时间则暂停/失败。明显设备离线暂停整条任务，不消耗五次网络尝试。
- 不重复五次：Key 错、余额不足、模型不存在，直接标记配置错误；在用户允许的已启用列表内可跳过不可用模型，记录原因。
- 上下文过长先按明确规则分块/缩减；内容拒绝终止该请求并解释，不能用跨服务商重试规避。格式错误最多一次受预算限制的修复，仍失败显示失败，不混同无响应。
- 流式中断保留“未完成”草稿，新尝试不得拼接另一模型的半句话；取消/重试可能已经计费。API 不支持幂等键时不承诺恰好计费一次。
- 跨服务商候选来自用户启用且已告知数据去向的排序列表；视觉任务只路由到符合能力的候选。若全部失败，保留原文和上次成功结果。
- 缓存键包括任务类型、输入哈希/版本、目标语言、模板版本、模型和参数。Token 以服务商统计为准，未知时保守估算并标估算；只知次数则不虚构金额。

任务状态统一为 queued、running、waitingConfiguration、waitingNetwork、succeeded、partial、failed、cancelled、interrupted。等待初始配置是调度就绪状态，尚未启动付费任务；真正进入队列时创建 deadline，此后排队、断网等待和退避均计入总时限，不能因切换状态重新计时。短暂断网可在剩余时限内恢复，deadline 到期则结束；服务进程被系统终止时记 interrupted，不能自动重放不确定是否计费的请求。重试阶段作为 running 的子阶段记录。

### 5.2 WebDAV 首发范围

共通偏好、非敏感模型/搜索配置、prompt/来源规则、订阅/分组、三态阅读与收藏纳入同步。API Key、WebDAV 密码、带秘密的订阅认证、设备路径/字体/背景文件、窗口布局、执行调度开关不同步。正文、图片、生成总结、阅读会话统计首发不自动同步；完整备份用于人工搬迁。

普通订阅 URL 可同步；若 URL 含 token 或认证，将秘密拆为本机凭据引用，其他设备提示补填，不能把完整私密 URL 放入快照。用户 prompt 也可能包含自行输入的秘密，导出/同步预览提示检查，不能宣称能自动发现所有敏感文字。

跨设备文章键采用共享 Feed syncId + 类型标记 + GUID（无 GUID 用规范 URL/稳定指纹）的确定性摘要。本机自增 ID 不外传；两台独立导入同一源时先按规范 URL 对齐 Feed 并保存别名。远端状态到达但本机没有正文，保存状态占位，后续抓取匹配；不把不存在的文章虚构成全文。不可靠兜底身份保留诊断而非误合并。

多写入服务须验证强 ETag/If-Match 等条件发布能力。协议使用不可变快照 + 共享 manifest：下载共同基线→三方比较→在本机暂存合并结果→上传唯一快照并读回校验→以条件写更新 manifest→本地事务确认成功。网络不能放在长数据库事务内；manifest 冲突重新读取/合并，最多 3 轮，之后等待重试。上传中断的孤儿快照不是当前版本。

同步开始时固定本地修订号和待上传变更集合，不长时间锁住界面。上传过程中产生的新本地修改必须保留为下一轮待同步变更；提交结果仅确认已包含的修订，不能整库覆盖当前数据或将所有 dirty 标记一并清空。远端发布成功但本机确认前崩溃时，重启根据快照 ID、父版本和修订集合恢复，重复确认必须幂等。

不同字段独立变更可合并；同字段并发（特别是 read/later/unread 与取消收藏）显示冲突，保留本机有效值和两个候选，用户选择后形成新版本。不得用三态逻辑 OR 或仅比较设备墙钟。删除订阅的保留收藏选择进入同步操作元数据，其他设备应用前展示破坏性影响；未批准不自动清除本地内容，保留待处理冲突。

不具备可靠条件发布的服务器降级为只读拉取或显式快照导入/导出，不开启不安全多端自动覆盖。删除使用墓碑，首发不自动清除；注销旧设备/压缩历史作为后续协议任务。重置同步数据需要备份和所有设备重新加入，不用悄悄丢墓碑节省空间。

### 5.3 清理、备份和统计

- 分类显示媒体、文章正文、新闻总结、设置/状态数据库、其他缓存与测量时间。清缓存只删可再生内容，不删付费 AI 结果、状态、订阅、prompt 或秘密。
- 自动媒体/正文/总结清理分别有开关与天数；默认关闭。收藏默认保护，later 默认保护；主动删除订阅不受自动清理保护规则阻止，必须在确认页说明。只释放正文时保留身份和状态，防止刷新把文章复活成未读。
- 总结引用用最小快照，不为了一个引用永久保留整篇正文。用户彻底删除时列出关联摘要/引用/缓存并清理，不能留下隐藏副本。
- 明文 ZIP 备份包含一致性数据快照、版本清单、校验和、可选媒体，排除凭据；提示“包含个人订阅/正文，任何持有者均可读取”。OPML 不是完整备份。使用 SQLite 备份机制而非复制活动数据库并遗漏 WAL。
- 恢复默认到新数据目录，先校验 schema、大小、路径、哈希，失败不动原库；正式切换前再次确认。旧版本不能写较新 schema。压缩包拒绝绝对路径和路径穿越。
- 统计首发本机有效阅读时长：前台可见且活跃时累计，失焦/锁屏/后台暂停，5 分钟无交互暂停；按会话时区跨午夜拆分。它是估计，不是精确阅读证明。热力图有 0 值/图例/日期分钟，七日柱状图有文字数据；可关闭并清空历史。

## 7. 美术与 UI 标准

极简、低饱和、编辑式阅读。优先内容与可读性，不使用大面积渐变/玻璃和虚构新闻封面。AI 直接绘制 SVG 图标，20/24 逻辑尺寸、1.5–2 视觉线宽；状态三选一占一个控件位置，收藏单独星形。应用图标先做小尺寸辨识验证，资源纳入 MIT/第三方声明。

动效 120–200ms，跟随减少动效设置；图标有读屏标签，图表有文字数据。中英、浅深、大字号、窄窗、旋转、输入法与辅助功能纳入验收。所有 UI 文案来自国际化资源；界面语言变化不重写历史 AI 输出。

## 8. 安全、性能与发布约束

- 不可信 RSS、HTML、图片、URL、OPML、同步快照、备份和 AI 输出均在边界校验。网页资料中的指令不能改变工具权限；prompt 防注入只是辅助，真正限制由客户端执行。
- 只允许 http/https 外链；自动发现的目标拒绝 loopback/链路本地/私网地址，解析 DNS 与每次重定向后再次验证并防止重新解析绕过；用户显式配置的本地服务独立授权。跨域跳转不带认证头，不全局忽略 TLS 证书。
- Keychain/Keystore 不等于整库加密或对已攻陷设备的保护。日志/截图/分享/备份不得泄露凭据，数据恢复不能退回明文秘密存储；没有安全存储时提示会话使用或失败。
- 首次数据发送与付费告知的确认记录保存在本机，并绑定提供商、目标端点和允许能力。同步来的配置不自动授予另一设备发送权限；端点或接收者发生实质变化时重新告知。确认记录属于运行授权状态，不作为普通偏好自动同步。
- 所有 I/O、大文本解析、图片解码/降采样按需移出 UI 阻塞路径。列表虚拟化、数据库索引、媒体 LRU、有界并发/重试/缓存，避免为了 AI 功能常驻浏览器或完整网页运行时。
- 性能验收集：100 个订阅、50000 条文章、100000 字符长文，声明硬件、系统和 release/profile 模式；首屏/已索引本地搜索 P95 初始目标不超过 1 秒，60Hz 常规滚动多数帧 16.7ms 内。包体积、安装大小、冷启动、静置/阅读内存、峰值、能耗必须记录；绝对内存上限在 M0 基线后批准，不能无测量宣称轻量。
- 新项目采用 MIT；包标识初定 io.github.guzhengsvt.flux，T006 必须确认维护者命名空间与旧应用冲突。如果沿用旧包标识可能触发升级覆盖，先明确独立数据目录/不兼容处理，未确认前不签正式包。
- GitHub 首发输出 macOS Apple Silicon 安装包及 Android ARM64 APK、校验和、签名/公证状态、发布说明。正式密钥由维护者保管，不生成后提交仓库。macOS 公证和 Android 自有签名需真实验证；不要求用户关闭系统安全机制。
- 版本检查只查询公开发布信息并打开外部下载页。自动安装、任意远端代码加载、账号体系、遥测上传、笔记、推荐和语义向量搜索均不在首发范围。
